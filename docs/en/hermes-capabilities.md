## Accepted planning architecture and priorities

Recommended: behavior adaptation through existing Rust contracts and remaining cards. This preserves one authority/data/lifecycle boundary and gives each feature independent regression/runtime acceptance. A Hermes execution backend would add a Python/provider/tool ecosystem and conflict with the current production policy; it is not this proposal. File-format interoperability can be designed later as an explicitly reviewed importer, without treating downloaded instructions as authority.

First extend planned G74 for gradual skill/reference loading and deferred typed tool discovery, G88 for scoped durable recall/contradictions/staged knowledge, and G89 for lineage/usage/evaluation snapshots. Bind their original dependencies, rather than declaring unsupported inference ready. Extend planned G51 for durable job/profile ownership and bounded specialist collaboration. G77/G79 hold reviewed experience-to-skill/recipe proposals and finite improvement/promotion; G64/G65 hold permitted ecosystem artifacts. Accepted G54/G63/G75/G87 receipts remain unchanged; additions are independently accepted consuming flows, not retrospective changes to accepted evidence. A scheduler is a distinct future implementation slice; no new daemon/cron/inference is activated by this research.

All imports, learned memory/skill/recipe candidates and explanations remain proposed until applicable source rights, purpose consent and held-out evaluation pass. Institution-private material stays inside its permitted project; a public-share candidate needs separate derivative/share permission and review. Anonymity cannot be inferred from removing a name. Runtime model changes preserve in-flight identities and require accepted capability/profile/data/resource compatibility. No fixed model brand is required by the behavior contracts.
