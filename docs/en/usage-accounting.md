# Project token and cost accounting

Revision **1.0.0**, 12 October 2026. [Türkçe](../tr/usage-accounting.md).

The maintainer requested project-wide historical token totals by model and reasoning effort, approximate cost and continued tracking in future work. The first-party [collector](../../tools/usage/collect.py) is local Python development tooling, using only the standard library. It makes no model, billing or network requests. Its ledger, configuration and reports are private local artifacts, excluded from Git. No session messages, tool results, credentials or private reasoning text are exported.

## Scope and evidence

A private configuration names `project_roots` and `session_roots` (Codex current and archived sessions). Exact directory ancestry selects registered roots; alternatively an existing checkout must have a GitHub origin in the fixed `eylema-dev` repository allowlist. Parent/fork IDs extend the selected session graph. A similarly named unrelated directory or repository does not enter the project. Register new roots before work begins; inspect selected session counts and coverage after refresh. Membership proves project association, not task authorization. A mixed-project conversation needs a separately curated metadata export instead of registering its entire root.

The collector uses `token_usage_record.usage`, keyed by provider and a hashed response identity, then joins the recorded turn's model/effort. It ignores cumulative event/thread/turn totals, which would double count repeated context, resumes and copied fork history. Duplicate identities must agree or the refresh fails and preserves the previous ledger. Input includes cached reads and cache writes; output includes reasoning. Total is input plus output; those subsets are never added again. Model/effort describe recorded configuration; hidden served model identity is not established. Missing model or effort remains `unknown`. Later recorded context may enrich an unknown model/effort without changing response tokens; conflicting known metadata still fails. Unknown observations never overwrite previously recorded known attribution; new responses without context remain unknown.

A ledger refresh is idempotent. Previously measured responses survive session archival/removal; disappearing source records do not reduce the historical total. Current sessions, scanned files, retained responses, sessions lacking response records and unpriced tokens are reported. Missing configured session directories or malformed complete discovery headers fail. Incomplete active headers/final lines are deferred and reported, including external exports; malformed complete records fail without exposing their contents. Cumulative-only sessions are reported as gaps, without estimating response usage. Missing metadata cannot silently establish zero consumption. The first refresh can recover only records still available locally; a missing old conversation, other account/device or unexported provider is outside measured coverage. Image-generation/search/computer-use tool charges are not inferred from language-model tokens.

Other providers may supply explicit, private normalized JSONL through `external_usage_files`. Each record contains exactly `provider`, `response_id`, `session_id`, `turn_id`, `timestamp`, `model`, `effort`, `tokens`. Stable IDs must identify the original response, not the export invocation. `tokens` contains `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, `reasoning_output_tokens`, `total_tokens`. Normalize input to include all cache portions; use provider-reported counts and retain unknown effort. External IDs do not select Codex sessions. Models without a reviewed price stay unpriced. An external exporter or future adapter must provide these metadata records; the collector does not automatically instrument every application/provider.

## Approximate costs

The checked-in [rate registry](../../tools/usage/rates.json) records the official pricing source and valuation date. This is a **Standard public API-equivalent USD estimate**, valued at that dated tariff across the observed history; it is not a reconstruction of historical paid invoices. ChatGPT/Codex subscription fees, credits/quota, tax, exchange rates and separate tools are excluded. Actual paid cost remains unknown until real billing evidence is supplied. Unknown model aliases, including an internal automatic reviewer, are counted but not assigned another model's price.

Per response, cost is `(uncached_input × input_rate + cached_input × cache_rate + cache_write_input × write_rate + output × output_rate) / 1,000,000`. For the currently inventoried GPT-6 models, input above 272,000 tokens doubles input/cache rates and multiplies output rates by 1.5 for the entire request. Reasoning effort changes measured usage; it does not add a second per-token surcharge. Decimal arithmetic avoids floating-point accumulation. An explicitly separate Fast API scenario is twice the Standard estimate; it is a hypothetical comparison, not proof of the actual service tier used by Codex.

Refresh prices from the official source when pricing changes. Review the dated registry through a PR, and preserve snapshots showing the earlier valuation. Revaluing historical usage at a new rate does not imply that the earlier invoice changed. New providers or aliases need explicit sourced pricing; never substitute a convenient model or invent a zero price.

## Continuing workflow

1. Keep the collector and reviewed rates in an accepted devguide checkout. Store the private configuration and output under an ignored local `work/usage` directory. Output directory permissions are 0700, output files 0600; concurrent refreshes share an advisory lock and atomic replacements per file. These are not a multi-file transaction: an IO failure may leave a newer ledger and stale report. History remains in the ledger; resolve the failure and rerun to regenerate the reports.
2. Run `python3 tools/usage/collect.py --config <private-config.json> --output <private-output-directory>`. The collector prints only totals and coverage. Inspect `latest.tr.md` for the human report, `latest.json` for daily UTC/model/effort totals, `ledger.json` for metadata-only response records and `snapshots.jsonl` for changed cumulative snapshots. Report timestamps state the cutoff; an in-progress response is recorded after completion.
3. Refresh before and after each Goal, including failed attempts and separate reviews. Record the report cutoff and cumulative/delta totals in local task evidence. The final completion response may appear only in the next refresh. Register new project checkouts, sessions or normalized provider exports before starting work and verify coverage afterward. Do not publish private reports or configuration in a PR.
4. A quiet hourly Codex thread heartbeat may refresh the same private reports. It must preserve current work, avoid provider calls/paid actions, remain quiet on unchanged/non-actionable usage and report only meaningful coverage failures or user-requested summaries. The heartbeat's own model usage is included on a later refresh. Desktop scheduling depends on the host/app being available; per-Goal refresh remains required.

The future-work requirement lives in the [contribution workflow](../../CONTRIBUTING.md). The scheduler is a local installation detail, not a GitHub CI job; hosted CI exercises synthetic parser regressions only and cannot read a contributor's session history. Preserve the ledger before uninstalling or moving the tool. Rollback removes the optional scheduled refresh and reverts tooling/policy through a reviewed PR without deleting measured history.

Sources: [OpenAI API pricing](https://developers.openai.com/api/docs/pricing), [GPT-6.1 Sol pricing and context rules](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [GPT-6 Luna pricing](https://developers.openai.com/api/docs/models/gpt-6-luna).
