# Tooling and dependency inventory

Revision **0.3.0**. [Türkçe](../tr/tooling.md).

The production target is owned Rust components with no third-party Cargo packages by default. This repository currently has no production code. CI tools do not become application dependencies. Linux, the browser, drivers, GPU interfaces and model artifacts are explicit platform inputs, not magically removed by using Rust.

Reproduce installation with `python -m pip install --require-hashes -r tools/requirements-ci.txt` in an isolated Python 3.14 environment. Updating a tool requires reviewing its release/provenance, resolving the complete dependency set, recording artifact SHA-256 values from PyPI, running tests with the new lock, and updating this inventory. GitHub action updates require an official release tag resolved to its full commit SHA. No automatic dependency updater is installed.

The first-party policy does not justify writing unreviewed cryptography, replacing standard schema validation for this docs-only phase, or claiming a complete Rust-only operating system. Changes to the production dependency boundary require an architecture proposal and maintainer decision. Minimal browser host bindings and shader sources must be explicitly inventoried at M3.

## Shared first-party validation tools

Tooling revision 0.3.0 lives in devguide. Repository-local copies of the validators, generic regression tests, lockfile, workflow, issue forms and PR template are listed with SHA-256 fingerprints in tools/vendor.json. Devguide integration compares every listed copy against this source; intentional repository-specific schema tests remain in core. Updating the source requires linked updates to consumers and their repository-set pins. These are first-party development tools, not runtime components. The Git CLI downloads pinned public snapshots as data with bounded subprocess timeouts; no additional package or service is required.

The rust-v1 profile currently permits only workspace-local packages and no build scripts, including in development targets. Cargo metadata is checked before compiling. Rust distribution/toolchain, macOS SDK and browser remain platform inputs; runtime provenance still requires review. Rustup is a development provisioning tool, not an application dependency. Training remains separately inventoried and uninstalled.

G04 adds an opt-in first-party Python 3.14 development doctor in core tools/doctor. It generates explicitly inventoried temporary Rust/Wasm/Metal smoke fixtures, verifies native ARM64 execution and compiler/linker outputs, and records a sanitized environment with source/tool/artifact hashes. This is separate local environment evidence; it does not enable runtime sources in documentation-v1 or prove GPU, browser, model or training execution. Rustup 1.29.1 and official Metal Toolchain installation are pinned in the core installation record. No new Python package, production crate, inference engine or privileged CI is added.

G05 adds devguide-only tools/check_goal_tracking.py using the existing Python 3.14 standard library and the observed GitHub CLI 2.102.0. It performs structural validation and opt-in bounded, read-only GitHub metadata requests; no automatic issue creation, administration mutation, provider call or production runtime is supplied. Its negative tests run in the existing unittest gate. The shared 0.3.0 tool/workflow copies remain unchanged.

G09 adds one owned core platform library and minimal first-party platform/browser/codec-host.mjs bindings. Production services are macOS libSystem/CommonCrypto SHA-256 and Security SecRandomCopyBytes; browser hosts require standard WebAssembly memory and WebCrypto digest/entropy. No crypto algorithm or external Cargo/npm runtime package is added. The opt-in tools/check_codec_platform.mjs harness uses the observed Node v26.11.1 only as a development host (node:fs/os/path/url/child_process/assert/crypto standard modules), requires macOS and delegates preflight to the unchanged Python/Rust gate. It actually executes Wasm and compares native bytes/hashes/failures; hosted CI still provides native tests and selected Wasm compilation, not this Node proof or browser acceptance. Core paired codec-platform docs inventory the SDK ABI, narrow unsafe FFI and trusted memory lifecycle. No npm installation, model inference or training environment is introduced.

## Local usage accounting

The optional first-party `tools/usage/collect.py` uses Python 3.14 standard-library JSON, decimal, filesystem, advisory locking and bounded Git metadata reads. It adds no package, production crate, model call, billing API or CI credential. Synthetic regression tests run in the existing unittest gate. Private response metadata and priced summaries remain in an ignored local directory; the [accounting workflow](usage-accounting.md) defines historical coverage, unknowns and future-task refreshes. Codex desktop scheduling is a local platform input; its own model usage must also be counted.

G27 adds model-repository-only tools/model_catalog.py and its eleven semantic unittest cases. It uses Python3.14 standard-library JSON/SHA256/struct/path/argparse only as an offline development audit/metadata encoder, not a production model engine. It binds source/config/license/template declared hashes, nine optional roles and authored operator records to exact model-profile.v1 EYL bytes consumed by owned core Rust tests. No network/provider/model/weight execution or installation occurs in the audit. Transformers0720e206 and pinned Qwen sources were read/hash-audited privately as references only; their code is neither vendored nor installed/executed. Production Rust/core ownership, canonical machine schemas and shared-tool fingerprints remain unchanged.
