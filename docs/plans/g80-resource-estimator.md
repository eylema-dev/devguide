> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with the already selected inline method. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce bounded, traceable resource estimates for cooperating local models, RAG and model-specific training without changing execution admission.

**Architecture:** A pure owned Rust module computes component byte intervals and combines them using explicit physical pools and overlap groups. Borrowed inputs and fixed-capacity output arrays avoid heap/device allocations and operational side effects. A sizing verdict never establishes execution support, permission or measured performance.

**Tech Stack:** Existing Rust 1.99.0 workspace and standard library; existing Python repository tooling. No new dependency or provisioning profile.

## Review Focus

1. Equal names with different owner/artifact/revision/backend/pool must not share weights; different invocations always retain separate state (Task 2).
2. Missing overlaps, stale evidence or missing available memory must remain unknown even when known subtotals are small (Task 2).
3. Packed quantized values and rational coefficients must round upward; group tails must not lose scale overhead (Task 1).
4. Unified and discrete memory cannot absorb each other's shortages or double-count the same physical pool (Task 2).
5. Training rank/layout/optimizer omissions and unsupported architecture must not become zero bytes or execution support (Task 1 and Task 3).

## Shared interface decisions

All following types live in `resource_estimate.rs`, are public unless marked private, and use `Clone, Copy, Debug, Eq, PartialEq` where their members permit. No implicit defaults supply coefficients. Input fields below are required; `Option` means explicitly not applicable only where stated.

| Type | Exact fields/variants and meaning |
| --- | --- |
| `ByteInterval` | `lower: u64, upper: u64`; constructor `new(lower: u64, upper: u64) -> Result<Self, EstimateError>` rejects reversed bounds |
| `Ratio` | `numerator: u64, denominator: u64`; numerator and denominator must be positive; each endpoint rounds upward after checked multiplication |
| `EstimateError` | `InvalidInput, LimitExceeded, DuplicateIdentity, DanglingReference, ConflictingIdentity, Overflow`; malformed input is an error, uncertainty is a report |
| `UnknownReason` | `MissingCoefficient, UnsupportedLayout, UnsupportedArchitecture, MissingOverlap, MissingBudget, StaleEvidence, IdentityMismatch, MissingIdentity` |
| `Evidence<'a>` | `origin: Origin, source: &'a str, revision: u64, valid_from: u64, valid_until: u64`; `Origin` variants `MeasuredArtifact, PublisherDeclaration, SuppliedAssumption`; inclusive validity window, reversed window invalid |
| `Claim<'a, T>` | `Known { value: T, evidence: Evidence<'a> }, Unknown { reason: UnknownReason, source: &'a str }`; no implicit unknown-to-zero conversion |
| `SizeStatus<'a>` | `Known(ByteInterval), Unknown { reason: UnknownReason, source: &'a str }, NotApplicable`; last variant only for explicit `Formula::NotApplicable` |
| `Formula<'a>` | `Bytes(ByteInterval)`, `Packed { elements: u64, bits: u32 }`, `Scaled { bytes: ByteInterval, ratio: Ratio }`, `Weights { resident_parameters: u64, active_parameters: Option<u64>, bits: u32, metadata: Claim<'a, ByteInterval> }`, `Quantized { parameters: u64, bits: u32, group_size: u64, scale_bytes: u64, metadata: Claim<'a, ByteInterval> }`, `Kv { context: u64, batch: u64, layers: u64, kv_heads: u64, head_width: u64, bits: u32 }`, `Recurrent { batch: u64, state_elements: u64, bits: u32, coefficient: Ratio }`, `RagVectors { count: u64, dimensions: u64, bits: u32 }`, `Lora { targets: &'a [LoraTarget], bits: u32, copies: Ratio }`, `Unsupported(UnknownReason)`, `NotApplicable` |
| `LoraTarget` | `input: u64, output: u64, rank: u64`; positive dimensions/rank, rank at most `min(input, output)`; duplicate target shapes allowed because separate layers may match |
| `Pool<'a>` | `id: &'a str, physical_id: &'a str, kind: PoolKind, capacity: Claim<'a, u64>, available: Claim<'a, u64>, reserve: Claim<'a, u64>`; `PoolKind` = `Unified, HostRam, DeviceVram, Storage`; available is gross remaining before declared reserve, usable = available minus reserve |
| `InstanceKey<'a>` | `profile: &'a str, revision: u64, artifact: [u8; 32], backend: &'a str, owner: &'a str, pool: &'a str`; all fields participate in exact equality |
| `Resident<'a>` | `id: &'a str, key: InstanceKey<'a>, expected_key: InstanceKey<'a>, weights: Claim<'a, Formula<'a>>`; one unique declared instance, several invocations may refer to it |
| `Invocation<'a>` | `id: &'a str, resident: &'a str, pool: &'a str, state: Claim<'a, Formula<'a>>, workspace: Claim<'a, Formula<'a>>`; requested settings reside in formulas, never inferred from observed use |
| `Auxiliary<'a>` | `id: &'a str, pool: &'a str, kind: AuxiliaryKind, lifetime: Lifetime, size: Claim<'a, Formula<'a>>`; kinds `ModelState, ConversionSource, ConversionDestination, Staging, Modality, RagIndex, RagSource, RagWorking, TrainingBase, Adapter, Gradient, Optimizer, Activation, Checkpoint, Temporary`; `Lifetime` = `Persistent, Transient` |
| `Member<'a>` / `Overlap<'a>` | `Member` = `Invocation(&'a str), Auxiliary(&'a str)`; `Overlap { id: &'a str, members: &'a [Member<'a>] }`; persistent auxiliary cannot appear in a group |
| `Snapshot<'a>` | `id: &'a str, expected_id: &'a str, revision: u64, expected_revision: u64, pools: &'a [Pool<'a>], residents: &'a [Resident<'a>], invocations: &'a [Invocation<'a>], auxiliary: &'a [Auxiliary<'a>], overlaps: Option<&'a [Overlap<'a>]>`; `None` means unknown schedule, `Some(&[])` explicit no transient work and invalid if transient work exists |
| `ComponentEstimate<'a>` | `id: &'a str, part: ComponentPart, pool: &'a str, status: SizeStatus<'a>, evidence: Option<Evidence<'a>>`; `ComponentPart` = `Weights, State, Workspace, Auxiliary`; unique `(id, part)` within globally unique entry IDs |
| `PoolEstimate<'a>` | `id: &'a str, total: Option<ByteInterval>, usable_budget: Option<u64>, verdict: Verdict`; `Verdict` = `EstimatedFit, ExceedsDeclaredBudget, Unknown` |
| `EstimateReport<'a>` | `snapshot: &'a Snapshot<'a>, snapshot_status: SizeStatus<'a>, components: [Option<ComponentEstimate<'a>>; 144], component_count: usize, pools: [Option<PoolEstimate<'a>>; 8], pool_count: usize, verdict: Verdict, planning_only: bool`; unused slots `None`; provenance/formulas remain traceable to borrowed immutable snapshot inputs; `planning_only` always true |

Units are represented by typed fields (`bits`, bytes, counts, seconds), not free-text unit conversion. All present counts/bits are positive; `Bytes([0,0])`, zero metadata and reserve are valid explicit values. Bits range 1..=64; packed elements are bit-packed continuously with `ceil(elements * bits / 8)`. `Kv` multiplies full requested context × batch × layers × KV heads × head width × 2 before packing. Recurrent applies the explicit ratio to its independently packed batch/state count. `Quantized` adds `ceil(parameters/group_size) * scale_bytes` plus explicit metadata. LoRA sums `rank * (input + output)` for every target, packs the complete adapter count, then applies `copies` (explicit gradients/optimizer factors); no universal optimizer coefficient. QLoRA base uses `Quantized`; adapter/gradients/optimizer/activations/checkpoints/staging are separate declared components. Unsupported NF4/custom layout becomes `UnsupportedLayout`; a bit count alone does not certify a format.

`Claim` wraps each auditable formula specification or explicit size. Its source covers all numeric fields as one declaration; component-specific metadata may have its own claim. Mixed provenance is represented by separate components or nested metadata evidence, never mislabeled measured. Unknown nested metadata propagates its named reason. Traceability includes both outer and nested claim via the snapshot; declarations are not authenticated. Explicit training/RAG/modality components and separate placements are caller responsibilities documented in Task 3; this API cannot discover omitted workload requirements.

## Task 2: Bounded portfolio, identity, overlap and physical-pool estimates

**Files:** Modify the same Rust module and test file only.

**Interfaces:** Consumes `component_interval`, `ByteInterval` and statuses from Task 1. Produces `pub fn estimate<'a>(snapshot: &'a Snapshot<'a>, now: u64) -> Result<EstimateReport<'a>, EstimateError>` plus the remaining shared interface types above.

Resident IDs/invocation IDs/auxiliary IDs are globally unique. Duplicate full instance key is rejected even under different IDs; consumers share one resident ID instead. Exact profile revision can differ across genuinely different instances; expected snapshot identity/revision binds the caller's requested set. Each resident also binds its complete requested `expected_key`: any mismatch yields `IdentityMismatch` for its weight and dependent invocation components; an all-zero artifact fingerprint yields `MissingIdentity`. Explicit `NotApplicable` is allowed for state/workspace/optional auxiliary only, never for a resident's required weights. Duplicate pool physical IDs reject aliases irrespective of kind; discrete pools must declare distinct physical IDs. Unknown/stale capacity/available/reserve cannot yield fit; known available <= capacity and reserve <= available or input is invalid. Capacity alone is never usable budget.

For each pool, sum resident weights and persistent auxiliaries exactly once. Each explicit overlap group sums its invocation state/workspace and transient auxiliaries, deduplicating nothing implicitly; repeated members within a group are invalid. Members across different groups are allowed alternatives. Every invocation/transient auxiliary must occur in at least one explicit group; omissions make that pool unknown. Add the maximum group lower and maximum group upper to persistent intervals. Storage follows the same bounded accounting but is a separate pool, never RAM/VRAM. `overlaps=None` sets every pool and snapshot status unknown; an explicit but incomplete schedule marks affected pools and snapshot status unknown. Any required unknown component or identity/freshness uncertainty yields `total=None` and `Unknown` for affected pools; known component subtotals remain in report entries, never advertised as a complete zero estimate. An empty portfolio yields explicit [0,0] totals only with valid known pool budgets and an explicit empty schedule. All sums are checked.

With complete totals, upper <= usable means `EstimatedFit`; lower > usable means `ExceedsDeclaredBudget`; otherwise `Unknown`. Overall verdict is Exceeds if any pool definitely exceeds; else Unknown if any pool unknown; else Fit. Snapshot identity mismatch makes all pools unknown with component reasons `IdentityMismatch` (`snapshot_status` carries identity/schedule uncertainty; Known[0,0] means declaration consistent). Malformed duplicate/dangling references remain errors, not uncertainty. `EstimateReport` never has a runtime-eligibility success field.
