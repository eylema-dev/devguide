## Objective and scope

Implement the existing `apps/eylema` bootstrap as the native CLI entrypoint for the G14 loopback service. Reuse the existing `eylema-web::protocol` request/result wire format, execution/task identifiers and machine error codes. Provide `start`, `inspect`, `run`, `stop`, and `doctor` commands with bounded input/output and explicit exits. Do not make a second task protocol, bypass host authorization, claim person identity, or expose non-loopback networking.

Allowed paths: `apps/eylema/**`, `Cargo.lock`, `README.md`, `README.tr.md`, `tools/translation-pairs.json`, `docs/en/local-cli.md`, `docs/tr/local-cli.md`, `docs/en/local-http.md`, `docs/tr/local-http.md`, and in devguide this plan, `tools/repository-set.json`, plus G14/G15 status/delivery records. The repository-set edit changes only the immutable core source revision to this Goal's reviewed head. Root workspace membership, guards, workflow, contracts, portable targets, other Goals, licenses, permissions, publication and spending stay out of scope. No third-party production dependency. The existing app is already a workspace member; source review must confirm whether its current path is the smallest implementation boundary before any additional workspace edit.

## Acceptance to checks

- G15-A1: CLI `run`, `inspect`, and `stop` use the same typed transport IDs and error codes as the native G14 service. Exercise a real loopback socket and child-process CLI against a real native journal; verify task/execution identity across client and service, structured success/error output, invalid identifier/request behavior and cancellation authorization/outcome. Test both denial for the stock non-human session and effective cancellation with a separately host-issued verified-human session; the CLI must not synthesize person verification.
- `start` composes owned host, journal, platform and web services on IPv4 loopback; it opens/creates the default owner-private Application Support store, uses bounded configuration and has a testable orderly shutdown path. The bearer/CSRF session file is mode0600 under a private directory; it is not placed in journal, logs, argv or public output. The stock session is non-human and narrowly scoped.
- `doctor` reports the existing private data path and authenticated service reachability with stable machine error codes and no mutation. Test missing, healthy and stopped service states. Startup tests new and reopened journals; never truncate/migrate silently.
- Preserve help/version behavior and unknown/non-Unicode argument failure. Add regression coverage for parsing, output limits and stable errors.
- Run exact six shared AGENTS commands and unchanged Rust fmt/clippy/test/build/Wasm gates, actual native CLI/service/journal integration, privacy/diff inspection, final-body CI, separate exact-head review, merge and exact-main CI/tree checks. Cross-repository pins and G14 accepted tracking must be updated with final immutable evidence.

## Risks and exclusions

CLI configuration can create a local secret-custody boundary; default to owner-private paths and explicit redaction. A local loopback bearer is not real-user authentication. Cancellation requires a service-issued verified-human capability and must not be fabricated by a CLI flag or caller claim. `Ctrl-C`/process lifetime is not durable cancellation. Native macOS execution is required; Linux/Wasm compilation does not prove macOS service or browser behavior. No deployment, release, license selection, administration, remote access, GPU/model/training, or performance acceptance.
